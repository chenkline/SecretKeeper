## 2. 为什么五端不共享代码

需求明确要求"使用各自平台的 native 方式实现，不要求跨平台方式，但移动平台不可以搞跨平台方式"，且经确认采用**五端完全独立原生实现**。

代价与应对：

| 代价 | 应对 |
|---|---|
| 密码学实现重复五遍 | 用 test-vectors/ 的黄金向量强制五端结果逐字节一致 |
| 格式解析重复五遍 | 以 docs/03-data 的字节级规范为准，不允许各端自定义 |
| 修复缺陷需改五处 | 缺陷修复 PR 必须同时包含五端；CI 门禁强制覆盖 |
| 行为容易漂移 | 需求文档逐条编号，测试用例按编号对应 |

**不共享代码，不等于不共享约定。** 共享的载体是文档与测试向量。

## 3. 各平台工程

### 3.1 Windows（windows/）

- 语言：C++17/C++20
- UI：WinUI 3（C++/WinRT）
- 构建：CMake 生成 VS 工程，或 MSBuild + `Microsoft.WindowsAppSDK` NuGet
- 密码学：CNG（`bcrypt.dll`）提供 Argon2id（Win 11 内置 `BCRYPT_ALGORITHM_ARGON2ID`）、RSA-OAEP、AES-GCM
- 存储：`sqlite3.dll`（自带 amalgamation），WAL 模式
- 文件对话框/分享：`IFileOpenPicker` / `IFileSavePicker`

注意：Win11 的 CNG 支持 Argon2id，但需确认目标系统最低版本；如需兼容 Win10，则 Argon2id 需回退到 libsodium 实现（libsargon2）。

### 3.2 Linux（linux/）

- 语言：C11/C17
- UI：Qt 6（Qt Widgets；如需更现代观感可用 Qt Quick）
- 构建：CMake + `qt_standard_project_setup`
- 密码学：libsodium（Argon2id、RSA 不含，需 OpenSSL 的 RSA-OAEP）或直接全用 OpenSSL 3
- 存储：SQLite3
- 托盘与全局快捷键：Qt 原生支持

注意：Qt 仅用于 Linux。Windows 端不使用 Qt。

### 3.3 macOS（macos/）

- 语言：Swift 5.9+
- UI：AppKit（按确认结论，不用 SwiftUI）
- 构建：Swift Package Manager + `xcodebuild`
- 密码学：CryptoKit（无 Argon2id）+ Security.framework（SecKey RSA-OAEP）
- Argon2id：需引入 `swift-sodium` 或 C 版 argon2 绑定
- 存储：SQLite3（系统自带 libsqlite3）
- 沙箱：需配置 App Sandbox，文件读写走 `NSOpenPanel`/`NSSavePanel`，容器目录为 `~/Library/Application Support`

注意：macOS 沙箱下不能随意读写任意路径，导出文件必须走用户选择的面板；这与"导出由用户指定路径"的需求一致。

### 3.4 Android（android/）

- 语言：Kotlin
- UI：Jetpack Compose（Material 3）
- 构建：Gradle + `com.android.application` 插件 + Gradle Version Catalog
- 密码学：Argon2id 需 `com.lambdapioneer.argon2kt` 或 `de.mkammerer:argon2-jvm`；RSA-OAEP 与 AES-GCM 用 `java.security`（AndroidKeyStore 可托管 RSA 密钥）
- 存储：Room 或直接 SQLite（Room 支持 SQLCipher 预留）
- 截屏防护：`FLAG_SECURE`
- 文件：Storage Access Framework（SAF），禁止直接依赖固定路径（Android 10+ 分区存储）

### 3.5 iOS（ios/）

- 语言：Swift
- UI：SwiftUI
- 构建：Xcode 工程 + Swift Package Manager 依赖；CI 用 `xcodebuild`
- 密码学：CryptoKit + Security.framework（`SecKeyCreateEncryptedData` 支持 `.rsaEncryptionOAEPSHA256`）
- Argon2id：`swift-sodium`
- 存储：SQLite3
- 截屏防护：iOS 无标准 API，可通过检测 `UIScreen.isCaptured` 提示，或遮罩视图

## 4. 各平台内部模块划分

每个平台工程内部保持相同的四层结构（命名按语言惯例调整）：

```
<platform>/
├── src/
│   ├── ui/            # 界面
│   ├── service/       # 业务用例
│   ├── storage/       # 索引库 + 容器编解码
│   └── crypto/        # 密码学原语
├── tests/             # 单元测试
└── (平台工程文件)
```

**crypto 层的公共接口在各端保持同名同语义**（如 `deriveKek`、`wrapWithRsa`、`encryptAesGcm`），便于对照实现与排查。

## 5. 共享测试向量目录

`test-vectors/` 是**唯一共享的代码资产**，存放形式为 JSON（便于各语言解析）：

| 文件 | 内容 |
|---|---|
| `kdf-argon2id.json` | 密码、盐、参数 → 期望 KEK（十六进制） |
| `aes-gcm.json` | 密钥、明文、IV、AAD → 期望密文与 Tag |
| `rsa-oaep.json` | 固定 RSA 密钥对、公钥、明文数据密钥 → 期望密文 |
| `container-roundtrip.json` | 完整容器字节流 → 期望解析结果 |
| `negative-cases.json` | 篡改输入 → 期望错误类别 |

每个向量必须包含**负例**（错误输入应产生何种错误），而不只是正例。

**CI 强制要求**：五端各自跑同一份向量，任何不一致直接失败。

## 6. 构建与运行约定

- 每个平台有独立的构建入口，CI 中 `working-directory` 指向对应目录。
- 统一输出目录约定不重要（各平台产物形态不同），但**测试结果必须可机读**，供 CI 汇总。
- 所有平台的测试都必须包含"跑 test-vectors 全量向量"这一步。

## 7. 提交约定

- 涉及格式或密码学的提交，diff 中必须包含 `test-vectors/` 与 `docs/03-data/` 的同步更新。
- 修复某个平台的缺陷，若属通用逻辑，必须在五端一并修复，并在提交信息中列出五个平台的变更。
- 不提交任何真实密钥、密码或导出文件。
