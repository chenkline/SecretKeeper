## 2. 代码共享范围

需求要求移动平台（Android / iOS）必须使用各自的原生方式实现；桌面三端（Windows / Linux / macOS）则**共享同一套 C++ 代码**。

| 平台 | 代码来源 | 一致性保障 |
|---|---|---|
| Windows / Linux / macOS | 共享 `src/common` + `src/include` + `src/<platform>` | 代码共享即一致，另加黄金向量复跑 |
| Android | 独立 Kotlin 实现 | 黄金向量强制逐字节对齐 |
| iOS | 独立 Swift 实现 | 黄金向量强制逐字节对齐 |

桌面三端共享带来三处直接收益：

- **密码学只实现一遍**：三端编译**同一份** `vendor/mbedtls` 与 `vendor/argon2`，
  一致性由「同一份实现」保证，而不是靠事后比对发现分叉。
- **格式解析只实现一遍**：容器编解码与索引库是共享代码，不存在各端自定义的可能。
- **修复缺陷只需改一处**：业务缺陷与界面缺陷的修复自动覆盖三端。

Android 与 iOS 仍是独立实现。它们靠 `test-vectors/` 的黄金向量与
docs/03-data 的字节级规范强制对齐；**规范与向量不一致时，以规范为准修正实现**，
不允许反向修改规范去迁就某个平台。

## 3. 各平台工程

### 3.1 Windows（windows/）

- 语言：C++17
- UI：FLTK 1.4.5（静态链接，无第三方 DLL 依赖）
- 构建：根 `CMakeLists.txt` + `build/windows`
- 密码学：**mbedTLS 3.6.7**（vendor 同源源码）提供 RSA-2048-OAEP、AES-256-GCM、SHA-256、CTR-DRBG 随机数；Argon2id 来自 `vendor/argon2` 参考实现（mbedTLS 不含 Argon2）
- 存储：`vendor/sqlite` amalgamation，WAL 模式
- 平台层：剪贴板、路径获取等少量 OS API 封装，集中在 `src/windows`

注意：Argon2id **不再依赖任何系统能力**——它与 mbedTLS 一样是内置源码，因此 Win10/Win11 行为完全一致。mbedTLS 是纯软件实现，RSA 恒可用，不存在系统能力探测。

### 3.2 Linux（linux/）

- 语言：C++17
- UI：FLTK 1.4.5（与 Windows 端同一份 vendor 源码）
- 构建：根 `CMakeLists.txt` + `build/linux`
- 密码学：**mbedTLS 3.6.7**，与 Windows 端**同一份 vendor 源码**；Argon2id 用 `vendor/argon2`
- 存储：`vendor/sqlite` amalgamation
- 平台层：X11/Wayland 剪贴板、路径获取，集中在 `src/linux`

依赖的系统库仅限 X11 生态（`libX11`、`libXext`、`libXft`、`libXinerama`、`libXcursor`、
`libXrender`、`libfontconfig`、`libfreetype`），不引入 Qt/GTK 等重量级工具包。

### 3.3 macOS（macos/）

- 语言：C++17
- UI：FLTK 1.4.5（与 Windows / Linux 端同一份 vendor 源码）
- 构建：根 `CMakeLists.txt` + `build/macos`
- 密码学：**mbedTLS 3.6.7**，与 Windows / Linux 端**同一份 vendor 源码**；Argon2id 用 `vendor/argon2`
- 存储：`vendor/sqlite` amalgamation
- 平台层：NSPasteboard 剪贴板、路径获取，集中在 `src/macos`

注意：不使用 App Sandbox，导出文件直接写入用户指定路径，与「导出由用户指定路径」的
需求一致；应用数据目录为 `~/Library/Application Support/SecretKeeper`。

### 3.4 Android（android/）

- 语言：Kotlin
- UI：Jetpack Compose（Material 3）
- 构建：Gradle + `com.android.application` 插件 + Gradle Version Catalog
- 密码学：Argon2id 需 `com.lambdapioneer.argon2kt` 或 `de.mkammerer:argon2-jvm`；RSA-OAEP 与 AES-GCM 用 `java.security`（AndroidKeyStore 可托管 RSA 密钥）
- 存储：Room 或直接 SQLite（Room 支持 SQLCipher 预留）
- 截屏防护：`FLAG_SECURE`
- 文件：Storage Access Framework（SAF），禁止直接依赖固定路径（Android 10+ 分区存储）

### 3.5 iOS（ios/）

- 语言：Swift
- UI：SwiftUI
- 构建：Xcode 工程 + Swift Package Manager 依赖；CI 用 `xcodebuild`
- 密码学：CryptoKit + Security.framework（`SecKeyCreateEncryptedData` 支持 `.rsaEncryptionOAEPSHA256`）
- Argon2id：`swift-sodium`
- 存储：SQLite3
- 截屏防护：iOS 无标准 API，可通过检测 `UIScreen.isCaptured` 提示，或遮罩视图

## 4. 桌面三端内部模块划分

桌面三端共用同一套四层结构，物理上落在仓库根的 `src/` 下：

```
src/
├── include/           # 各层公开头文件
│   ├── container/     # 容器格式
│   ├── crypto/        # 密码学原语
│   ├── store/         # 索引库 + 文件读写
│   └── core/          # 业务用例
├── common/            # 上述四层的跨平台实现
├── windows/           # 平台层 + FLTK 界面
├── linux/
└── macos/
```

四层依赖方向严格单向：**界面 → 业务 → 存储 → 密码学**。
`common/` 内的代码**不得**引用任何平台 API；确需 OS 能力时（剪贴板、用户目录等），
由 `src/<platform>/` 提供薄封装供界面层调用。

**crypto 层的公共接口在各端保持同名同语义**（如 `derive_kek`、`wrap_with_rsa`、
`encrypt_aes_gcm`），便于 Android / iOS 对照实现与排查。

## 5. 共享测试向量目录

`test-vectors/` 是**唯一共享的代码资产**，存放形式为 JSON（便于各语言解析）：

| 文件 | 内容 |
|---|---|
| `kdf-argon2id.json` | 密码、盐、参数 → 期望 KEK（十六进制） |
| `aes-gcm.json` | 密钥、明文、IV、AAD → 期望密文与 Tag |
| `rsa-oaep.json` | 固定 RSA 密钥对、公钥、明文数据密钥 → 期望密文 |
| `container-roundtrip.json` | 完整容器字节流 → 期望解析结果 |
| `negative-cases.json` | 篡改输入 → 期望错误类别 |

每个向量必须包含**负例**（错误输入应产生何种错误），而不只是正例。

**CI 强制要求**：五端各自跑同一份向量，任何不一致直接失败。

## 6. 构建与运行约定

- 每个平台有独立的构建入口，CI 中 `working-directory` 指向对应目录。
- 统一输出目录约定不重要（各平台产物形态不同），但**测试结果必须可机读**，供 CI 汇总。
- 所有平台的测试都必须包含"跑 test-vectors 全量向量"这一步。

## 7. 提交约定

- 涉及格式或密码学的提交，diff 中必须包含 `test-vectors/` 与 `docs/03-data/` 的同步更新。
- 修复某个平台的缺陷，若属通用逻辑，必须在五端一并修复，并在提交信息中列出五个平台的变更。
- 不提交任何真实密钥、密码或导出文件。
