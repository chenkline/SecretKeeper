# 测试与验收方案

## 1. 测试目标

| 目标 | 判定标准 |
|---|---|
| **跨平台一致** | 五端对同一输入产生**逐字节相同**的输出 |
| **密码学正确** | 全部向量通过，无自行实现原语 |
| **格式健壮** | 畸形输入不崩溃、不越界、不误接受 |
| **功能完整** | 需求文档每条功能均有对应用例 |
| **安全行为生效** | 五项基础安全功能可验证 |
| **无静默跳过** | 任何一层 `skipped` 必须为 0，跳过即构建缺陷 |

## 2. 测试分层

| 层次 | 范围 | 运行时机 | Windows 端当前自检项数 |
|---|---|---|---|
| **向量测试** | 黄金测试向量，跨平台一致性的核心 | 本地子集 + CI 全量 | 91（`scripts/verify-vectors.py`） |
| 密码学层自检 | KDF / RSA-OAEP / GCM / 随机数 | CI + 本地 `-Test` | 86 |
| 存储层自检 | 索引库 + 原子写 + 限额 + 悬空引用 | CI + 本地 `-Test` | 81 |
| 核心层自检 | 码点计数 / 退避 / KEK 槽位 / 错误文案 | CI + 本地 `-Test` | 178 |
| 业务层自检 | 主密钥与机密信息十二项操作 | CI + 本地 `-Test` | 54 |
| 单元测试 | 各端容器编解码、限额校验、退避计算 | CI |
| 集成测试 | 完整业务流程（生成→加密→导入→解密） | CI |
| 性能测试 | 派生耗时、内存峰值 | CI 记录，不硬性门禁 |
| 手工验收 | UI 交互、黄色问号、掩码、锁定体验 | 发布前人工 |

## 3. 黄金测试向量

### 3.1 存放位置与格式

路径：仓库根 `test-vectors/`，JSON 格式（便于五端解析）。

### 3.2 向量清单

| 文件 | 覆盖内容 |
|---|---|
| `kdf-argon2id.json` | Argon2id 派生：固定密码+盐+参数 → 期望 32 字节 KEK |
| `aes-gcm.json` | AES-256-GCM：固定密钥/nonce/AAD → 期望密文与 Tag |
| `rsa-oaep.json` | RSA-OAEP-SHA256：固定密钥对 + 数据密钥 → 期望封装结果 |
| `container-roundtrip.json` | 完整容器字节流 ↔ 期望解析结果 |
| `char-count.json` | 字符计数：含 emoji / 生僻字 / 组合字符的边界用例 |
| `negative-cases.json` | 畸形输入 → 期望错误类别 |

### 3.3 向量格式示例

```json
{
  "name": "argon2id-basic-1",
  "kdf": {
    "alg": "argon2id",
    "version": 19,
    "password": "746573742d70617373776f726421",
    "salt": "000102030405060708090a0b0c0d0e0f",
    "memoryKiB": 10240,
    "iterations": 3,
    "parallelism": 1,
    "outputLen": 32
  },
  "expected": "b6a5c1e0f2...（64 位十六进制）"
}
```

**注意**：向量中的 password 用**十六进制 UTF-8 字节**表示，避免 JSON 转义或编码差异引入歧义。

### 3.4 负例向量

负例必须指定**期望错误类别**，而非仅"失败"：

| 类别 | 含义 |
|---|---|
| `wrong_password` | 密码错误（GCM 认证失败） |
| `bad_magic` | 文件类型不匹配 |
| `unsupported_version` | 版本过高 |
| `truncated` | 数据截断 |
| `length_mismatch` | 长度字段与实际不符 |
| `tampered_ciphertext` | 密文被篡改（认证失败） |
| `unknown_algorithm` | 未知算法标识（如 SM2 在 v0.0.1） |

### 3.5 执行要求

每个平台的测试套件必须：

1. 加载 `test-vectors/` 下**全部** JSON 文件。
2. 对每个正向向量验证输出**逐字节相等**。
3. 对每个负例向量验证抛出**指定类别**的错误。
4. 任一不符 → 测试失败，CI 红灯。

**五端必须使用同一份向量文件，不允许各端自定义。**

## 4. 测试用例

### 4.1 跨平台一致性（最高优先级）

| 编号 | 用例 | 期望 |
|---|---|---|
| C1 | 五端用同一密码+盐派生 KEK | 32 字节完全相同 |
| C2 | 五端 AES-256-GCM 加密相同输入 | 密文+Tag 相同（nonce 固定时） |
| C3 | 五端 RSA-OAEP 封装相同数据密钥 | 256 字节密文相同 |
| C4 | 五端解析同一容器文件 | 各字段一致 |
| C5 | 字符计数：含 emoji 的 150 字符边界 | 五端计数一致 |
| C6 | 十六进制 ID ↔ 二进制 ID 转换 | 往返一致 |

### 4.2 格式健壮性

| 编号 | 用例 | 期望 |
|---|---|---|
| F1 | Magic 错误 | 返回 `bad_magic` |
| F2 | 版本号过高 | 返回 `unsupported_version` |
| F3 | Payload 长度与实际不符 | 返回 `length_mismatch` |
| F4 | TLV 长度超出剩余 | 解析失败，不崩溃 |
| F5 | 密文被篡改 1 字节 | GCM 认证失败 |
| F6 | 盐被篡改 | 派生错误 KEK → 认证失败 |
| F7 | 空文件 / 1 字节文件 | 解析失败，不崩溃 |
| F8 | TLV 长度字段为 0xFFFFFFFF | 解析失败，不越界分配 |

**F5–F8 是必须覆盖的安全测试**，任何越界读取或崩溃都是严重缺陷。

### 4.3 主密钥功能

| 编号 | 用例 | 期望 |
|---|---|---|
| M1 | 生成首个主密钥 | 自动成为默认主密钥 |
| M2 | 生成第二个主密钥 | 成为备选，不影响默认 |
| M3 | 生成第三个主密钥 | 被拒绝，提示需先导出删除 |
| M4 | 导出后导入（往返） | 数据一致，ID 保留 |
| M5 | 导入时保护密码错误 | 提示"主密钥密码错误" |
| M6 | 切换默认主密钥 | 需验证新旧两个密码 |
| M7 | 删除默认主密钥 | 被拒绝 |
| M8 | 删除备选主密钥 | 需密码 + 导出确认 |
| M9 | 删除主密钥后其机密信息 | 机密信息仍在，主密钥 ID 后显示黄色问号 |
| M10 | 导入已达上限时 | 被拒绝，提示先导出删除 |

### 4.4 机密信息功能

| 编号 | 用例 | 期望 |
|---|---|---|
| S1 | 添加机密信息（默认主密钥） | 无需额外密码，成功保存 |
| S2 | 添加机密信息（非默认主密钥） | 需输入并验证该主密钥密码 |
| S3 | 明文 150 字符 | 允许 |
| S4 | 明文 151 字符 | 拒绝并提示 |
| S5 | 第 16 条机密信息 | 被拒绝，提示先导出删除 |
| S6 | 导出后导入（往返） | 明文一致 |
| S7 | 导入时主密钥不在本地 | 提示"导入失败，请先导入主密钥" |
| S8 | 导入时密文被篡改 | 提示"导入失败，解密错误" |
| S9 | 详情：主密钥缺失 | 黄色问号 + 空名称 + 6 个 `*` |
| S13 | 列表：主密钥存在但名称为空 | 名称列为空，**ID 后无问号**，与 S9 可区分 |
| S14 | 列表：主密钥存在且名称非空 | 名称列正常显示，ID 后无问号 |
| S15 | 公私钥 nonce 不同 | 生成主密钥后 `pubKeyNonce != privKeyNonce` |
| S10 | 详情：非默认主密钥 | 需密码才显示明文 |
| S11 | 删除非默认主密钥的机密信息 | 需密码，否则拒绝 |
| S12 | 删除前未确认导出 | 拒绝删除 |

### 4.5 安全功能

| 编号 | 用例 | 期望 |
|---|---|---|
| E1 | 闲置达到阈值 | 自动锁定，界面回到锁屏 |
| E2 | 锁定时检查内存 | KEK 槽位与程序随机密钥已清零 |
| E3 | 解锁成功后 | 立即触发一次程序随机密钥轮换 |
| E4 | 连续 30 秒空闲 | 定时轮换，KEK 密文迁移槽位 |
| E5 | 迁移后检查原槽位 | 原槽位仍存在（诱饵不清除） |
| E6 | 复制机密信息 | 剪贴板写入，按时长清除 |
| E7 | 详情窗口失焦 | 明文立即隐藏 |
| E8 | 应用进入后台 | 明文隐藏 + 触发轮换 |
| E9 | 密码连续错误 | 第 n 次后等待 2^(n-1) 秒 |
| E10 | 错误 10 次后 | **仍可继续尝试**，仅等待变长 |
| E11 | 成功输入后 | 计数清零 |

### 4.6 性能测试

| 编号 | 指标 | 目标 |
|---|---|---|
| P1 | Argon2id 派生耗时 | ≤300ms（记录各 runner 实测值） |
| P2 | 派生峰值内存 | ≤10MiB |
| P3 | 添加/查看机密信息响应 | 无感知延迟 |
| P4 | 列表加载（15 条） | 无卡顿 |

性能**不作为硬性门禁**（设备差异大），但需记录基线，若某端显著劣化需在 PR 中说明。

## 5. CI 门禁

合并到主干**必须**满足：

- [ ] 五个平台 job 全部构建成功
- [ ] 五端黄金向量测试全绿
- [ ] 格式健壮性测试（F1–F8）全绿
- [ ] 无新增编译警告（视为错误处理）
- [ ] 四层自检的 `skipped` 均为 **0**（mbedTLS 是纯软件实现，RSA 无跳过理由）

**不阻塞但需知晓**：性能基线记录、覆盖率报告。

## 6. 测试向量生成

向量应由**可信第三方实现**生成，而非本项目代码自证。建议用 Python `argon2-cffi` + `cryptography` 生成初始向量，五端实现去对齐。

理由：若用项目自身的实现生成向量，五端同时错时无法发现。

生成脚本放在 `scripts/gen-vectors.py`，产出物提交到 `test-vectors/`。

校验用 `python scripts/verify-vectors.py`，当前 **91 项**全部通过。

## 7. 密码学实现专项检查

换密码学库时，除跑向量外还须人工确认以下项（mbedTLS 3.6 的具体坑位见 [AGENTS.md](../../AGENTS.md) 第 9.5 节）：

- [ ] 所有 mbedTLS 返回值判定使用 `rc < 0`，无 `rc != 0`
- [ ] GCM 加密路径在 `crypt_and_tag` 前调用了 `setkey`，且位数为 `key_len * 8`
- [ ] `rsa_gen_key` 之后显式 `set_padding(PKCS_V21, SHA256)`
- [ ] 主密钥公钥与私钥使用**不同** nonce
- [ ] OAEP 使用空 label，MGF1 与 OAEP 哈希均为 SHA-256
- [ ] 解密输出缓冲区按 `plain_size()` 计算，未把 tag 计入密文长度
- [ ] 未编入任何 mbedTLS 私有头（如 `rsa_internal.h`）
