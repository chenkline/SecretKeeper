# 密码学与密钥派生设计

> 本文档描述密匣的全部密码学决策。字节级数据格式见 [数据格式与存储设计](../03-data/数据格式与存储设计.md)。

## 1. 密钥层级

```
                        ┌─────────────────────────────┐
   用户输入的主密钥密码 ──┤ Argon2id(password, salt)    │
                        └──────────────┬──────────────┘
                                       │ KEK (32 bytes)
                        ┌──────────────▼──────────────┐
   主密钥私钥 (RSA) ─────┤ AES-256-GCM(KEK)            │
                        └──────────────┬──────────────┘
                                       │
   ┌───────────────────────────────────▼────────────────────┐
   │ 密文信息： {salt, argon2 参数, nonce, tag, RSA 私钥密文} │
   └────────────────────────────────────────────────────────┘

   添加机密信息时：
   ┌──────────────────┐
   │ CSPRNG → 数据密钥 │ (AES-256, 每条独立)
   └────┬─────────┬────┘
        │         │
   AES-256-GCM    │ RSA-OAEP-SHA256(主密钥公钥)
   加密机密信息    │ 封装数据密钥
        │         │
        ▼         ▼
   ┌──────────────────────────────┐
   │ {标题, nonce, tag, 密文,     │
   │  被封装的数据密钥, 主密钥ID} │
   └──────────────────────────────┘
```

**要点**：主密钥的**公钥与私钥均以 KEK 加密后落盘**，磁盘上不存在明文密钥材料。默认主密钥的 KEK 常驻内存（经程序随机密钥包裹，见总体技术设计），因此用默认主密钥加密时用户无需输入密码；只有非默认主密钥才需要验证密码。KEK 由用户密码派生，密码强度是整个安全模型的根基。

## 2. 密钥派生（KDF）

### 2.1 算法选择

| 算法 | 结论 |
|---|---|
| PBKDF2 | 纯 CPU，可被 GPU 大规模并行，抵抗离线爆破能力最弱 |
| bcrypt | 72 字节输入截断，参数固定 4KB 工作区，内存成本低 |
| scrypt | 抗 GPU，但需要较大连续内存且实现易出错 |
| **Argon2id** | **采用**。密码学竞赛冠军，抗 GPU 与旁路攻击，参数灵活 |
| bcrypt/scrypt/Argon2i | Argon2i 抗旁路、Argon2d 抗 GPU，**Argon2id 兼具两者**，为通用场景首选 |

### 2.2 参数

| 参数 | 值 | 说明 |
|---|---|---|
| 算法 | Argon2id | |
| 版本 | 0x13 | Argon2 v1.3，**固定** |
| 内存 m | 10 MiB = 10240 KiB | 满足"不超过 10MB"的约束 |
| 迭代 t | 3 | |
| 并行度 p | 1 | 单线程，避免多核并行削弱成本 |
| 输出长度 | 32 字节 | KEK |
| 盐 | **每条记录独立 16 字节随机**，明文随记录保存 | |

内存成本约 10 MiB/次，符合"推导耗费内存最好在 10MB 以内"。

### 2.3 性能预算

| 指标 | 目标 | 校验方式 |
|---|---|---|
| 单次派生耗时 | ≤300ms | 各平台 CI 基准测试，超标即警告 |
| 峰值内存 | ≤10MiB | Argon2id m=10MiB 决定，另有少量缓冲区 |
| 派生后残留 | 立即清零 | 代码审查 + 内存测试 |

实际耗时取决于设备。CI 在标准 runner 上测量并记录；若中端 Android 机超标，允许按平台下调 `t`，但**必须五端取同一组参数**，否则数据不互通。参数变更属于破坏性变更，必须递增格式版本并提供迁移。

### 2.4 盐策略（本仓库的关键设计决策）

需求原文要求："相同的输入密码，每次推导出相同的加密密钥；相同的输入密码在不同设备上推导出相同的加密密钥；相同的输入密码在不同平台版本程序版本中推导出相同的加密密钥。"

若采用全局固定盐，可字面满足该要求，但存在严重问题：**相同密码的所有记录会得到相同 KEK**，一处泄露即导致全部主密钥私钥泄露。

本仓库的解法是**每条记录随机盐 + 盐随记录明文保存**：

- 同一份记录 + 同一密码 → 任意设备/平台/版本得到**相同** KEK（因为盐来自该记录本身），满足互操作；
- 不同记录即使密码相同 → KEK **不同**，满足机密隔离。

因此"相同密码推出相同 KEK"的正确语义是**"相同密码 + 相同盐"**，而盐是记录的固有属性，随记录移动。这既满足跨平台一致性，又不牺牲安全性。

## 3. RSA-2048 主密钥

### 3.1 角色

- **公钥**：封装数据密钥。虽然公钥在密码学上属于公开信息，本项目**仍将其加密后落盘**，以避免密钥材料在磁盘上明文暴露、降低被批量提取的风险。
- **私钥**：解封装数据密钥。**必须保密**，以 KEK 加密形式落盘。
- 公钥与私钥**各自独立加密**，使用同一个 KEK 但**必须使用两个互不相同的随机 nonce**。

### 3.2 参数

| 项目 | 值 |
|---|---|
| 模长 | 2048 位 |
| 公钥指数 e | 65537 |
| 填充 | OAEP |
| OAEP 哈希 | **SHA-256（显式指定，不使用库默认）** |
| OAEP 标签 | 空（空标签是标准做法，跨库兼容性最好） |
| MGF1 哈希 | SHA-256 |
| 可封装明文上限 | 2048/8 − 2×32 − 2 = **190 字节** |

数据密钥为 32 字节，远低于 190 字节上限，无封装风险。

**跨库一致性要点**：OpenSSL、mbedTLS、CryptoKit、Java Security 对 OAEP 的实现细节（尤其 MGF1 是否与 OAEP 哈希一致）可能不同，必须逐端验证并写入黄金向量。

Windows 与 Linux 已固定使用 **mbedTLS 3.6.7**（同一份 vendor 源码），因此这两端之间不存在
实现差异；风险集中在 Windows/Linux 与其余三端之间。

### 3.3 私钥存储格式

私钥按平台原生格式序列化后，用 AES-256-GCM 加密：

| 平台 | 私钥序列化格式 |
|---|---|
| Windows | **PKCS#8 DER**（mbedTLS `mbedtls_pk_write_key_der`） |
| Linux | PKCS#8 DER（同一份 mbedTLS 源码） |
| macOS / iOS | PKCS#8 DER（Security.framework 导出） |
| Android | PKCS#8 DER（Java `KeyFactory` 导出） |

**注意**：私钥密文是本端生成、本端解密的，不跨端流动；跨端流动的是**导出文件**，导出时会重新序列化（见数据格式文档）。公钥则按 **PKCS#1 RSAPublicKey DER** 存取。

### 3.4 mbedTLS 实现要点（Windows / Linux）

mbedTLS 3.6 的若干 API 与 2.x 差异很大，且部分行为**编译通过但运行失败**。以下为已实测的要点，完整清单见 [AGENTS.md](../../AGENTS.md) 第 9.5 节。

| 事项 | 要点 |
|---|---|
| 错误判定 | mbedTLS **只用负数**表示错误，一律 `rc < 0`。`mbedtls_pk_write_*_der` 成功时返回**写入长度**，用 `rc != 0` 判定会把成功当失败 |
| DER 写入方向 | `asn1write` **从缓冲区末尾向前**写，编码起点是 `buf + size - len`；因此 PKCS#1 公钥必须**先写 E 再写 N**，否则得到 `SEQUENCE { e, n }` |
| MPI 编码 | `mbedtls_asn1_write_mpi()` **已输出完整 INTEGER**（tag+len+符号位补零+值），不能再包一层 tag/len |
| PKCS#1 公钥 | 3.6 把 RSAPublicKey 编解码移入私有头 `rsa_internal.h`。本地基于公开 API（`asn1` / `asn1write` / `rsa_import` / `rsa_export`）自实现 `write_pkcs1_pubkey` / `parse_pkcs1_pubkey`，**不得编入私有头** |
| PK 上下文 | `mbedtls_pk_setup()` 只分配自己的 rsa 上下文，不接受外部 key；`mbedtls_rsa_info()` 已移除，改用 `mbedtls_pk_info_from_type(MBEDTLS_PK_RSA)`。`MBEDTLS_PRIVATE(pk_ctx)` 是 `private_pk_ctx`，外部不可赋值 —— 正确做法是 `pk_setup` 后用 `mbedtls_pk_rsa()` 取回指针填充 |
| RSA 生成 | `mbedtls_rsa_gen_key(ctx, f_rng, p_rng, nbits, exponent)` 是 5 参无 seed。生成后 `hash_id` 留 `MBEDTLS_MD_NONE`，**必须**显式 `mbedtls_rsa_set_padding(&rsa, MBEDTLS_RSA_PKCS_V21, MBEDTLS_MD_SHA256)`，否则得到一把无法封装任何东西的密钥 |
| OAEP 签名 | PSA 风格。封装 `(ctx, f_rng, p_rng, label, label_len, ilen, input, output)`；解封 `(ctx, f_rng, p_rng, label, label_len, olen, input, output, output_max_len)`。空 label（`nullptr, 0`）即标准 OAEP，与 `rsa-oaep.json` 的 `label: null` 一致。解析后校验 `mbedtls_pk_get_type(&pk) == MBEDTLS_PK_RSA` 再显式 `set_padding`，不依赖 DER 里恢复的哈希值 |
| 随机数 | CTR-DRBG，由 `mbedtls_ctr_drbg_seed()` 播种 mbedTLS entropy；entropy 的平台源在 Windows 上是 `BCryptGenRandom`，故链接 `bcrypt.lib` |
| PSA | `MBEDTLS_PSA_CRYPTO_C` **保持关闭**。关闭时 3.6 的经典入口即为 PSA 风格签名（本项目已按此实现），开启反而需维护 PSA 属性配置 |
| 裁剪 | 只追加 `vendor/mbedtls/include/mbedtls/mbedtls_config.h` **末尾的 override 块**，不内联改写上游行，便于将来同步新版产生可 review 的 diff |

## 4. AES-256-GCM

### 4.1 参数

| 项目 | 值 |
|---|---|
| 算法 | AES-256-GCM |
| 密钥 | 32 字节 |
| IV/Nonce | **12 字节**，每次加密全新随机 |
| Tag 长度 | **16 字节** |
| AAD | 主密钥文件用 `masterKeyId`；机密信息文件用 `secretId` |

### 4.2 三处用法

1. **保护主密钥公钥**：`AES-256-GCM(KEK, pubKeyNonce, AAD=masterKeyId, plaintext=公钥DER)`
2. **保护主密钥私钥**：`AES-256-GCM(KEK, privKeyNonce, AAD=masterKeyId, plaintext=私钥DER)`
3. **加密机密信息**：`AES-256-GCM(数据密钥, dataNonce, AAD=secretId, plaintext=机密信息UTF-8)`

> ⚠️ **公钥与私钥的 nonce 必须不同。** 同一 KEK 下复用 nonce 会使两次加密的密钥流完全相同，攻击者无需密钥即可由 `pubKeyCipher XOR privKeyCipher` 恢复两者的异或值，机密性彻底失效。

### 4.3 认证失败处理

GCM 认证标签校验失败时**必须**返回认证失败错误，且**不得**区分"密文被篡改"与"密钥错误"——该区分会形成 oracle 泄漏信息。对外统一映射为需求文档规定的文案。

## 5. 随机数

所有随机数来自各端 CSPRNG：

| 平台 | 来源 |
|---|---|
| Windows | mbedTLS CTR-DRBG（熵源 `BCryptGenRandom`） |
| Linux | mbedTLS CTR-DRBG（熵源 `getrandom()`） |
| macOS / iOS | `SecRandomCopyBytes` 或 `SystemRandomNumberGenerator` |
| Android | `java.security.SecureRandom` |

**禁止**使用 `Math.random()`、`rand()`、C# `Random` 等非密码学随机源。

> ⚠️ **DRBG 必须先播种再取数。** 进程内 DRBG 为惰性构造的单例，首次使用时执行 `mbedtls_ctr_drbg_seed()`，失败即整个密码学层不可用。

随机数用途与长度：

| 用途 | 长度 |
|---|---|
| Argon2id 盐 | 16 字节 |
| AES-GCM Nonce | 12 字节 |
| 数据密钥 | 32 字节 |
| RSA 密钥对 | 由密码库生成 |
| 程序随机密钥 | 32 字节 |
| 主密钥 ID / 机密信息 ID | 16 字节（UUIDv4 语义） |

## 6. 内存安全

### 6.1 清零要求

| 密钥材料 | 生命周期 | 清零时机 |
|---|---|---|
| KEK | 派生后使用 | 使用完毕立即 |
| 数据密钥 | 解密时派生/读取 | 解密完成立即 |
| 主密钥私钥明文 | 解密时 | 使用完毕立即 |
| 机密信息明文 | UI 展示期间 | 清空界面时立即 |
| 程序随机密钥 | 常驻 | 锁定时立即 |
| KEK 密文各槽位 | 常驻 | 锁定时立即 |

### 6.2 实现要点（按语言）

| 语言 | 做法 |
|---|---|
| C++ | `std::vector<uint8_t>` + `SecureZeroMemory`/`explicit_bzero`；避免 `std::string` 承载密钥 |
| C | 固定大小 `uint8_t buf[N]` + `memset_s`/`explicit_bzero`（禁用可能被优化掉的 `memset`） |
| Swift | `Data` + `resetBytes(in:)`；避免 `String` 承载密码 |
| Kotlin/Java | `byte[]` + `Arrays.fill(arr, 0)`；避免 `String` 承载密码 |

### 6.3 UI 层的特殊约束

- 密码输入框必须禁用自动纠错（iOS/macOS 尤其注意，否则系统会缓存明文）。
- 明文展示界面失焦、窗口隐藏、应用进入后台时立即隐藏明文（需求已确认纳入 v0.0.1）。
- 复制机密信息到剪贴板后，按设定时长清除剪贴板（需求已确认纳入 v0.0.1）。
- 移动端启用截屏防护（Android `FLAG_SECURE`；iOS 至少做 `isCaptured` 提示）。

### 6.4 交换文件与休眠文件

内存中的密钥可能被换出到磁盘。各端按平台能力尽量规避：iOS/macOS 使用 `NSFileProtectionComplete` 并避免 `isExcludedFromBackup` 冲突；Android 使用 `FLAG_SECURE`；桌面端无法完全避免，应在文档中如实说明该残留风险。

## 7. 密码错误处理

- 校验密码时派生 KEK 并尝试解密主密钥私钥；GCM 认证失败即密码错误。
- 连续失败计数，指数退避 `delay(n) = min(2^(n-1), MAX_DELAY) 秒`，**不永久锁死**（需求明确要求"超过次数仍然可继续尝试"）。
- 计数与退避状态仅存内存，不落盘。
- 错误提示文案固定为需求文档规定的"主密钥密码错误"，不区分底层失败原因。
