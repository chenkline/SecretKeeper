# 机密信息与主密钥功能设计

> 本文档是 v0.0.1 的**修订版**功能规格，与 [需求原文](../机密信息加密应用需求功能设计.txt) 一一对应。差异之处已在文末"与需求原文的差异"列出。实现以本文档为准。

## 0. 术语与全局规则

| 术语 | 含义 |
|---|---|
| 主密钥 | 一个 RSA-2048 密钥对，有唯一 ID 与名称 |
| 默认主密钥 | 当前用于加密新机密信息的主密钥，同一时刻恰好一个 |
| 备选主密钥 | 非默认主密钥的其他主密钥 |
| 机密信息 | 一条加密记录，含主密钥 ID、可选标题、加密后的内容 |
| KEK | 由用户密码经 Argon2id 派生的密钥加密密钥 |

### 全局规则

- 长度单位为**字符（Unicode 码点）**。
- v0.0.1 限额：主密钥 2 个、机密信息 15 条、单条机密信息 150 字符。
- 任何密码输入错误统一提示"主密钥密码错误"，不区分底层失败原因。
- 密码输入框不回显、不自动纠错、不自动大写。
- 所有导出文件内容与本地数据文件逐字节一致。

---

## 1. 密钥派生

用户输入主密钥密码后，经 **Argon2id**（m=10MiB、t=3、p=1、输出 32 字节、**每条记录独立 16 字节随机盐**）派生 KEK。

一致性保证：同一份记录 + 同一密码，在**任意设备、任意平台、任意版本**上派生出相同 KEK，因而可互相解密。不同记录即使密码相同，KEK 也不同。

参数细节见 [密码学与密钥派生设计](../02-crypto/密码学与密钥派生设计.md)。

## 2. 主密钥管理

### 2.1 查询主密钥列表

- 列出全部主密钥。
- 每行显示：**主密钥 ID**、**名称**、**是否默认主密钥**。

### 2.2 生成主密钥

**流程**

1. 用户输入主密钥名称与主密钥密码（需二次确认）。
2. 程序读取该记录预分配的随机盐，用 Argon2id 派生 KEK。
3. 程序生成 **RSA-2048 密钥对**作为主密钥。
4. 用 KEK 以 AES-256-GCM 加密**私钥**，与公钥、名称、ID、盐、参数一同写入主密钥文件。
5. 若这是应用内第一个主密钥，自动设为默认主密钥。

**要点**

- **公钥明文存储**（无需保密），**私钥经 KEK 加密后存储**。
- 公钥用于**加密数据密钥**；私钥用于**解密数据密钥**。
- 若当前主密钥数量已达 2，提示用户需先导出并删除部分主密钥。

### 2.3 导出主密钥

**流程**

1. 用户选择主密钥。
2. 用户设置一个**保护密码**。
3. 用保护密码派生 KEK（新盐），用该 KEK 加密主密钥私钥，生成与本地主密钥文件**同格式**的字节流。
4. 写出为 `.smkexp» 文件。

**要点**：导出文件中的主密钥 ID、公钥、名称与本地一致；盐与私钥密文为新生成。

### 2.4 导入主密钥

**流程**

1. 用户选择导出的 `.smkexp» 文件。
2. 用户输入**保护密码**与**新的主密钥密码**。
3. 用保护密码派生的 KEK 解出主密钥。
4. 用新主密钥密码派生**新的 KEK**（新盐），重新加密主密钥，保存到本地主密钥文件。
5. 导入的主密钥作为**备选主密钥**（不会自动成为默认主密钥）。

**错误提示**

| 情况 | 提示 |
|---|---|
| 保护密码错误 | 主密钥密码错误 |
| 文件格式非法 / Magic 不匹配 | 导入失败，请选择正确的导出文件 |
| 文件版本过高 | 导入失败，文件版本过高 |
| 主密钥数量已达 2 | 请先导出并删除部分主密钥后再导入 |

### 2.5 切换主密钥

**流程**

1. 用户选择一个备选主密钥。
2. 程序要求验证**原默认主密钥密码**。
3. 程序要求验证**新默认主密钥密码**。
4. 两项均通过后完成切换。

**要点**：应用内第一个主密钥在生成时自动成为默认主密钥。

### 2.6 删除主密钥

**前置条件**

- **禁止删除默认主密钥**。
- 删除前必须提示用户导出主密钥备份，并提供两个选项：**立即导出** / **已经导出**。未选择则不允许删除。
- 必须输入正确的主密钥密码。

**要点**：删除主密钥时**不删除**由它加密的机密信息。这些机密信息此后进入"找不到主密钥"状态。

### 2.7 默认主密钥 KEK 缓存机制

为避免频繁派生，程序在内存中缓存默认主密钥的 KEK，但按以下方式加固：

1. 程序启动时生成随机对称密钥 —— **程序随机密钥**。
2. 用程序随机密钥以 AES-256-GCM 加密默认主密钥 KEK，得到 KEK 密文。
3. KEK 密文与程序随机密钥**分散保存**在内存的不同结构中，不存在同时包含两者的连续对象。
4. 内存中为 KEK 密文准备 **3 个备选槽位**。每次重新加密时，随机迁移到另一个槽位，**原槽位不清除**（作为诱饵）。
5. **轮换时机**：每 30 秒定时器、**每次解锁成功后**、每次从后台回到前台。
6. 锁定时立即清零所有槽位与程序随机密钥。

该机制提高内存转储的直接攻击成本，但不替代锁屏密码。

## 3. 机密信息管理

### 3.1 查询机密信息列表

- 列出全部机密信息。
- 每行显示：**主密钥 ID**、**主密钥名称**、**标题**。
- 无标题时标题列显示为空。
- 若主密钥不在本地主密钥列表中，在主密钥 ID 后显示一个**黄色问号**，表示未找到主密钥（此时主密钥名称显示为空）。

### 3.2 添加机密信息

**流程**

1. 用户输入机密信息文本（≤150 字符）与可选标题。
2. 用户从主密钥列表中选择使用的主密钥，列表显示**主密钥名称**；默认自动选定当前默认主密钥。
3. 程序生成随机 **AES-256 数据密钥**。
4. 用数据密钥以 AES-256-GCM 加密机密信息。
5. 用主密钥**公钥**以 RSA-OAEP-SHA256 封装数据密钥。
6. 将主密钥 ID、被封装的数据密钥、机密信息密文组合保存到机密信息文件。
7. 若机密信息条数已达 15，提示用户需先导出并删除部分机密信息。

**权限规则**：若用户选择的**不是**默认主密钥，必须输入并验证该主密钥密码。

**长度校验**：按 Unicode 码点计数，超过 150 字符时立即提示并阻止提交。标题长度建议同样限制。

### 3.3 导出机密信息

- 用户选择一条机密信息，导出其数据文件内容。
- 导出内容与机密信息文件内容**完全一致**，扩展名为 `.sscexp»。

### 3.4 导入机密信息

**流程**

1. 用户选择 `.sscexp» 文件。
2. 程序读取其中的主密钥 ID，在本地主密钥列表中查找。
3. 逐级处理（见下表）。

| 情况 | 提示 |
|---|---|
| 主密钥 ID 在本地找不到 | 导入失败，请先导入主密钥 |
| 解密数据密钥或机密信息失败 | 导入失败，解密错误 |
| 解密成功但写入本地失败 | 导入失败，保存出错 |
| 全部成功 | 导入成功 |

**密码规则**：若导入机密信息对应的主密钥**不是**当前默认主密钥，程序提示用户输入主密钥密码。输入界面需**同时显示主密钥 ID 和主密钥名称**以防混淆。KEK 解密失败则提示"主密钥密码错误"并要求重新输入。

### 3.5 查询机密信息详情

**显示内容**：主密钥 ID、主密钥名称、机密信息标题、机密信息明文。

**降级显示规则**

| 情况 | 显示 |
|---|---|
| 主密钥不在本地列表 | 主密钥 ID 后加**黄色问号**，主密钥名称**显示为空**，明文用 **6 个 `*»** 代替 |
| 主密钥不是当前默认主密钥 | 提示输入正确的主密钥密码，否则不显示明文 |

**安全行为**

- 界面失焦、窗口隐藏、应用进入后台时立即**隐藏明文**。
- 提供复制按钮，复制后按设定时长**清除剪贴板**。

### 3.6 删除机密信息

**前置条件**

- 删除前提示用户导出机密信息并妥善备份，提供**立即导出** / **已经导出**两个选项。
- 若该机密信息对应的主密钥**不是**当前默认主密钥，必须输入正确的主密钥密码，否则拒绝删除。

## 4. 基础安全功能（v0.0.1 新增）

以下条目在需求原文中未列出，经确认纳入 v0.0.1。**这些功能不改变数据格式，只影响 UI 与内存行为。**

### 4.1 闲置自动锁定

- 用户无操作达到设定时长后自动进入锁定状态。
- 默认时长建议 5 分钟，可在设置中调整。
- 锁定时：清空内存中的 KEK 缓存（含全部 3 个槽位与程序随机密钥）、隐藏所有明文、清除筛选与选中状态。
- 解锁需输入默认主密钥密码。

### 4.2 解锁后轮换程序随机密钥

- 每次解锁成功后**立即**执行一次程序随机密钥轮换（重新加密 KEK 密文并随机迁移槽位）。
- 与 30 秒定时轮换相互独立，定时器在解锁后重新计时。

### 4.3 剪贴板定时清除

- 用户点击"复制"后，将机密信息明文写入剪贴板。
- 在设定时长（建议 30 秒）后**清空剪贴板**。
- 若系统剪贴板不可写（如部分移动端后台），需静默失败并正常提示。

### 4.4 离开窗口隐藏明文

- 明文详情窗口失焦、最小化、切换标签或应用进入后台时，立即用掩码替换明文。
- 回到前台后需重新验证（若对应非默认主密钥）才能再次显示。

### 4.5 密码错误次数限制与指数退避

- 记录连续密码错误次数（**仅存内存**，不落盘）。
- 第 n 次失败后，下一次尝试前需等待：`delay(n) = min(2^(n-1) 秒, 上限)»，上限建议 60 秒。
- **超过次数后仍可继续尝试**，需求明确要求不永久锁死。
- 成功输入一次密码后，计数清零。
- 退避期间锁定输入框并显示剩余等待时间。
